# 数据库同步刷新功能测试指南

## 测试目的

验证在 WebDAV 同步下载数据库文件后，应用能够正确重新建立数据库连接并刷新所有相关数据。

## 测试前准备

1. 准备两个不同的数据库文件：
   - 本地数据库：包含一些测试数据（账户、交易等）
   - 远程数据库：包含不同的测试数据
2. 确保 WebDAV 服务器正常工作
3. 确保控制台日志可见（调试模式）

## 测试步骤

### 步骤 1：准备初始状态

1. 打开应用，查看当前显示的数据
2. 记录当前的账户数量、交易数量等关键信息
3. 截图保存当前界面状态

### 步骤 2：上传当前数据库

1. 进入 WebDAV 配置页面
2. 输入正确的服务器配置信息
3. 点击"上传数据库"按钮
4. 确认上传成功

### 步骤 3：修改本地数据

1. 返回主界面
2. 添加一些新的交易记录
3. 创建新的账户
4. 记录修改后的数据状态

### 步骤 4：下载远程数据库

1. 返回 WebDAV 配置页面
2. 点击"下载数据库"按钮
3. 确认下载操作
4. **关键观察点**：观察控制台日志输出

### 步骤 5：验证数据刷新

1. 观察界面是否立即更新
2. 检查数据是否恢复到上传前的状态
3. 验证新添加的数据是否已被远程数据替换
4. 检查各个页面（资产、负债、收入、支出）的数据是否正确

## 预期结果

### 控制台日志应该显示：

```
[WebdavConfigPage] 数据库下载成功，正在刷新应用数据...
[GlobalRefreshService] 开始全局数据刷新...
[GlobalRefreshService] 数据库连接刷新触发器已更新: X
[DatabaseProvider] 关闭数据库连接
[DatabaseProvider] 创建新的数据库连接实例
[GlobalRefreshService] DAO providers 已刷新
[GlobalRefreshService] 所有业务 providers 已刷新
[GlobalRefreshService] 全局数据刷新完成
```

### 界面表现应该：

1. 显示蓝色提示："数据库同步完成，应用数据已刷新"
2. 所有页面的数据立即更新为远程数据库的内容
3. 不需要手动刷新或重启应用
4. 数据变化应该在所有相关界面同步显示

## 测试检查点

### ✅ 成功标准

- [ ] 控制台输出正确的刷新日志
- [ ] 界面显示刷新完成提示
- [ ] 数据立即更新为远程内容
- [ ] 所有页面数据保持一致
- [ ] 图表和统计数据正确更新
- [ ] 无需重启应用

### ❌ 失败情况

- [ ] 界面数据没有更新
- [ ] 控制台出现错误日志
- [ ] 部分页面数据不一致
- [ ] 需要手动刷新才能看到新数据
- [ ] 应用崩溃或卡死

## 故障排除

### 如果数据没有更新：

1. 检查控制台日志，查看是否有错误
2. 确认数据库文件是否正确下载
3. 尝试重启应用作为对比
4. 检查 WebDAV 配置是否正确

### 如果出现错误：

1. 记录完整的错误信息
2. 检查网络连接状态
3. 验证 WebDAV 服务器可访问性
4. 确认数据库文件格式正确

## 性能测试

### 大数据量测试

1. 准备包含大量数据的数据库文件（>1000 条交易）
2. 执行同样的下载刷新流程
3. 观察刷新时间和内存使用情况
4. 验证界面响应性

### 频繁刷新测试

1. 连续执行多次下载操作
2. 观察是否有内存泄漏
3. 检查数据库连接是否正确关闭和重建

## 注意事项

1. **数据备份**：测试前务必备份重要数据
2. **网络环境**：确保网络稳定，避免下载中断
3. **测试环境**：建议使用测试数据，避免影响生产数据
4. **日志记录**：保存测试过程中的日志输出，便于问题诊断
